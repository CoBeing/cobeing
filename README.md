# CoBeing · 个人 AI 能力与共生网络

**People, personal AI agents, memories and digital resources — connected on their own terms.**

**CoBeing 不是一个需要用户每天打开的 App。** 它是个人聊天助手、WorldDesk 以及未来其他独立应用共同使用的后台身份、记忆、资源连接与授权网络。

日常用户体验由各自应用承担；CoBeing 仅在注册登录、记忆同步、设备关联、分享授权和数据管理等必要时提供后台能力与轻量管理入口。

## 两项核心基础能力

| 能力 | 范围 | 主要价值 |
| --- | --- | --- |
| **Personal Mesh** | **一个人自己的能力网络** | 将个人设备、Local Bridge、已装 Agent、MCP Provider、私人 Vault 和 Cloud Claw/Bot 组织为可发现、可授权调用的资源 |
| **CoBeing Network** | **不同人和他们 Agent 之间的共生网络** | 双方建立关系，在明确同意下发现、请求和共享有限能力、记忆片段及协作结果 |

**两者不是两套独立平台。** Personal Mesh 解决个人资源自治；CoBeing Network 连接多个自治的 Personal Mesh。关系成立不等于授予设备、文件、消息或详细记忆访问权限。

## 应用与能力

- **个人聊天助手**：围绕“帮我聊”开展沟通建议、关系记忆、主动选择文本和确认发送。
- **WorldDesk**：专注观察、研究、桌面 Agent 操作台及用户授权的任务协作。桌面版可打包通用 Local Bridge。
- **未来其他应用**：通过同一份身份、记忆及授权接口获得网络能力，而不需要复制整个 CoBeing 前端。
- **Local Bridge**：独立的通用本地能力桥（已有 Codex、WorkBuddy、Pi、MCP/Provider 等）；不依赖 CoBeing 才能工作。
- **Cloud Claw / Bot**：用户自有或获许可的云端 Agent；CoBeing 不要求用户迁移到自建统一模型平台。

**CoBeing Core / Basic** 提供共享控制面：稳定用户身份、少量受控基础记忆、私有资源目录、关系确认、具体授权与撤销。任务推理、桌面/通讯应用操作由用户已有节点完成。

## 核心设计原则

- **应用优先**：CoBeing 后台化，上层应用独立发展，品牌不强制露出；涉及数据处理与跨服务授权必须透明。
- **能复用不重建**：Local Bridge、用户已有云 Agent、微信等现有客户端继续独立维护。
- **默认私有**：节点登记不等于配对或在线，成为好友不等于授权共享。用户选定什么内容可以跨界。
- **最小数据**：Basic Memory 是按用户隔离的托管记录，不是所有聊天与文件的中央仓库，也不声称完全端到端加密。
- **逐步开源**：公开稳定有用的架构与实现；实验中间产物和第三方适配先在 Private 孵化，整理后再独立发布。

**状态：R0 早期孵化。** 公共仓库介绍方向、原则与规范；并不代表节点配对、远程任务和跨人能力共享已交付。可运行组件成熟后分别开放。
